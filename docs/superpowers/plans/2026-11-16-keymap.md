# Map phím tùy chỉnh + xoay camera bằng chuột — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Chơi game 3D trong ApkStart bằng bàn phím + chuột: phím tự do → chạm, joystick 360° WASD, xoay camera bằng chuột khi khóa con trỏ, trình chỉnh kéo-thả phủ lên game.

**Architecture:** `agent.ps1` (C# đã có hook chuột) bắt thêm bàn phím + chuột thô khi map phím bật, nuốt các phím đã gán và đẩy sự kiện ngay lập tức về Node. Toàn bộ logic (trạng thái khóa/nhả, joystick, camera, quy đổi tọa độ) nằm trong module JS thuần `src/core/keymap.js` để unit test. Chạm đa điểm gửi vào Android qua gRPC của Android Emulator (`src/core/touch.js`). Trình chỉnh + nhãn phím là một cửa sổ Electron trong suốt đặt trên vùng hình (HTML không vẽ đè được cửa sổ Qt nhúng).

**Tech Stack:** Electron, Node ≥20, C# trong PowerShell 5.1 (`Add-Type`), Android Emulator gRPC (`@grpc/grpc-js` + `@grpc/proto-loader`, phụ thuộc mới duy nhất).

**Spec:** `docs/superpowers/specs/2026-11-16-keymap-design.md`

## Global Constraints

- Giao diện và thông báo bằng tiếng Việt; comment code tiếng Việt như phần còn lại của dự án.
- `src/core/win/agent.ps1` giữ UTF-8 BOM; `src/core/win/windowctl.ps1` giữ thuần ASCII (test kiểm tra). File JS: LF, UTF-8 không BOM.
- Hook chỉ cài khi cửa sổ app ở tiền cảnh; mất focus / thu nhỏ / đóng / tác tử thoát → nhả chuột (`ClipCursor(NULL)`) và gỡ ngay.
- Phím cố định: **`** (VK 0xC0) = khóa/nhả chuột; **Esc** = bật/tắt menu (gửi Back Android) + nhả/khóa; **F12** (đổi được) = tắt/bật toàn bộ map phím.
- Lúc mở game chuột **chưa khóa**. Khi đang nhả: click chuột đi thẳng vào game như chạm thường, **không** tự khóa; WASD và phím khác vẫn hoạt động.
- Tọa độ lưu theo tỉ lệ 0–1 của màn hình Android; bộ phím lưu kèm `landscape`; lệch hướng → tạm tắt map phím + thông báo, không tự khởi động lại.
- Ngưỡng độ trễ spike: chuột di chuyển → chạm gửi vào Android **≤ ~30 ms**. Không đạt bằng gRPC lẫn `sendevent` → **dừng và báo người dùng**.
- Không macro, không auto-fire, không tay cầm, không xuất/nhập file.
- `npm test` phải xanh (trừ test "Ma trận thử lại" vốn đã lỗi trên máy ít RAM từ trước).

### Task 2: Lõi map phím thuần (`keymap.js`)

**Files:**
- Create: `src/core/keymap.js`
- Test: `test/auto-test.js` (thêm nhóm `[keymap.js]`, theo đúng kiểu `test()`/`assert()` hiện có)

**Interfaces:**
- Produces:
  - Kiểu `Control`:
    - `{ id: string, type: 'key', x: number, y: number, key: string, label?: string, releaseMouse?: boolean }`
    - `{ id: string, type: 'joystick', x: number, y: number, r: number, keys: { up: string, left: string, down: string, right: string } }` — `r` là bán kính theo tỉ lệ **chiều cao** màn hình.
    - `{ id: string, type: 'camera', x: number, y: number, w: number, h: number }` — tâm + kích thước theo tỉ lệ.
    - `key` là tên mã kiểu `KeyboardEvent.code` (`'KeyW'`, `'Space'`, `'Tab'`, `'Digit1'`…) hoặc `'Mouse1'`/`'Mouse2'` cho chuột trái/phải.
  - Kiểu `Profile = { version: 1, landscape: boolean, sensitivity: number, controls: Control[] }`, `sensitivity` mặc định `1.0`.
  - `defaultTemplate(landscape: boolean): Profile` — bố cục mẫu kiểu PUBG (giá trị bên dưới).
  - `vkToCode(vk: number): string | ''` và `codeToVk(code: string): number` — chữ A–Z, số 0–9, F1–F12, Space, Tab, Escape, Backquote, ShiftLeft, ControlLeft, AltLeft, Enter, Backspace, phím mũi tên.
  - `joystickVector(down: Set<string>, keys): { x: number, y: number }` — mỗi trục −1/0/1, đường chéo chuẩn hóa về độ dài 1; hai phím ngược nhau triệt tiêu.
  - `class KeymapEngine`:
    - `constructor({ profile: Profile, screen: { w: number, h: number }, emit: (touches) => void, onLock: (locked: boolean) => void, onBack: () => void, disableKey?: string })` — `disableKey` mặc định `'F12'`; `touches` cùng dạng `TouchChannel.send`.
    - `keyDown(code: string): boolean`, `keyUp(code: string): boolean` — trả `true` nếu phím thuộc map phím (bên gọi nuốt phím).
    - `mouseButton(code: 'Mouse1' | 'Mouse2', down: boolean): boolean` — chỉ xử lý khi `state === 'locked'`.
    - `mouseMove(dx: number, dy: number): void`
    - `reset(): void` — nhấc mọi ngón, về `unlocked`, gọi `onLock(false)` nếu đang khóa.
    - `get state(): 'unlocked' | 'locked' | 'disabled'`
    - `swallowCodes(): string[]` — các mã agent phải nuốt ở trạng thái hiện tại (`disabled` → chỉ `[disableKey]`).
  - `module.exports = { defaultTemplate, vkToCode, codeToVk, joystickVector, KeymapEngine }`

Giá trị `defaultTemplate(true)` (tỉ lệ x, y): joystick WASD `(0.14, 0.72)` `r 0.16`; camera `(0.70, 0.40)` `w 0.56 h 0.60`; Mouse1 Bắn `(0.80, 0.52)`; Mouse2 Ngắm `(0.92, 0.42)`; Space Nhảy `(0.88, 0.64)`; KeyC Ngồi `(0.82, 0.82)`; KeyZ Nằm `(0.92, 0.84)`; KeyR Nạp đạn `(0.70, 0.74)`; KeyF Nhặt `(0.60, 0.60)`; Tab Túi đồ `(0.06, 0.30, releaseMouse)`; KeyM Bản đồ `(0.95, 0.12)`; Digit1 `(0.50, 0.90)`; Digit2 `(0.57, 0.90)`. Bản dọc dùng cùng tỉ lệ (người dùng tự kéo lại).

Quy tắc engine (chép từ spec):
- Ngón: joystick `id 1`, camera `id 2`, phím thứ i `id 3 + i`.
- Joystick: có ít nhất một phím hướng đang giữ → ngón ở `tâm + vector * r * screen.h`; lần đầu thì `down` ở tâm trước rồi mới `move`; nhả hết → `up`.
- Camera (chỉ khi `locked`): lần di chuyển đầu → `down` tại tâm vùng; mỗi `mouseMove` cộng `dx * sensitivity`, `dy * sensitivity` (pixel Android); điểm mới ra ngoài vùng → `up` tại điểm cũ, `down` lại tại tâm, rồi áp phần dịch chuyển đó; mở khóa → `up`.
- **`** (Backquote): `unlocked ↔ locked`. Esc: luôn `onBack()`; `locked → unlocked`, `unlocked → locked`. Phím `releaseMouse`: chạm như thường + đảo khóa giống Esc (không gọi `onBack`). `disableKey`: `→ disabled` (gọi `reset` trước) / `disabled → unlocked`.
- Ở `disabled`: mọi phím trừ `disableKey` trả `false`, không chạm.
- Phím đã `down` trước khi đổi trạng thái: `keyUp` vẫn gửi `up` đúng ngón đó (không gửi `up` cho ngón chưa từng `down`).

**Interfaces:**

- Produces:
  - Lệnh mới `{"cmd":"km","on":0|1,"locked":0|1,"vks":"87,65,83,68,…"}` → trả `{"ok":true,"hooked":true|false}`.
  - Sự kiện mới (gửi **ngay từ luồng hook**, ghi socket dưới cùng một `lock` với `Reply`, không chờ vòng `Serve`):
    `{"ev":"kd","vk":N}`, `{"ev":"ku","vk":N}`, `{"ev":"mb","b":1|2,"d":1|0}` (chỉ khi `locked`), `{"ev":"mm","dx":N,"dy":N}` (chỉ khi `locked`), `{"ev":"kmlost"}` (tự nhả vì cửa sổ tiền cảnh không còn là cửa sổ app).
  - `WinAgent.setKeymap(on: boolean, { locked: boolean, vks: number[] }): Promise<{ ok: boolean, hooked: boolean }>` — idempotent như `setHook`; `dispose()` gửi thêm `{"cmd":"km","on":0}`.

Hành vi C#:
- `km on` cài `WH_KEYBOARD_LL` (13) trên **cùng** luồng hook (cài chuột nếu chưa có). Phím có VK trong `vks` → báo `kd/ku` và `return 1`; phím khác đi tiếp. Bỏ qua sự kiện có cờ `LLKHF_INJECTED`. Lặp phím do giữ (autorepeat) chỉ báo `kd` lần đầu.
- `locked = 1`: `ClipCursor` về hình chữ nhật 1×1 tại tâm vùng LCD; `WM_MOUSEMOVE` → `dx/dy = pt − tâm`, `return 1`; nút trái/phải → `mb`, `return 1`. `locked = 0` hoặc `km off` hoặc `HookOff` → `ClipCursor(IntPtr.Zero)`.
- Khi `km on`: ánh xạ chuột cũ (phải = Back, con lăn, nút bên) chỉ áp dụng lúc `locked = 0`.
- Trong callback: `GetForegroundWindow()` không phải cửa sổ host đã nhúng → `ClipCursor(NULL)`, đặt `locked = 0`, báo `kmlost`.
- Tiến trình agent thoát (kể cả bị kill) → Windows tự bỏ `ClipCursor` khi tiến trình sở hữu desktop input mất; thêm `ClipCursor(NULL)` trong handler `AppDomain.ProcessExit` cho chắc.
